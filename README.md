# CQA — Conversation Quality Analytics · команда Gashtar

Прототип для хакатона Freedom Broker. Система оценивает работу оператора в чатах и звонках по настраиваемому чек-листу, показывает обоснование по каждому критерию со ссылкой на реплику и поддерживает апелляции с решением проверяющего.

**Команда Gashtar**

- **Арсен** — фронтенд (интерфейс, Web Components)
- **Амиржан** — бэкенд, оценка через LLM, ручная разметка и сравнение моделей
- **Әміре** — тестирование

**Что умеет**

- **Оценка.** Загрузка диалогов по `group_id` из API организаторов или из JSON. Оценка оператора на RU, KZ и EN. По каждому критерию система показывает ответ, баллы, вес, объяснение и реплику-доказательство. Если действие пропущено, указывает проверенный участок, если стоит N/A — причину. Итог и баллы по секциям пересчитываются с перераспределением веса N/A.
- **Чек-листы.** Редактор критериев: формулировка, вес, тип ответа, разрешён ли N/A, шкала. Каждое сохранение создаёт новую версию.
- **Работа с результатом.** Карточка диалога: клик по доказательству ведёт к реплике, для звонков есть плеер записи. Апелляция по критерию, решение проверяющего, пересчёт итога. Видны исходная оценка, решение и финальный результат.

**Стек:** Python 3.10+ (только стандартная библиотека), SQLite, фронтенд на HTML, CSS и vanilla JS (Web Components, без сборщика — готов к встраиванию как HTML-компонент Dynamics 365). Модель — любой OpenAI-совместимый API или Anthropic. Рекомендуется **DeepSeek V4.1 Flash**.

## 1. Запуск за 3 шага

Нужен только **Python 3.10+**, устанавливать пакеты не нужно. На Windows вместо `python3` используйте `python`.

**Шаг 1. Скачать проект**

```bash
git clone https://github.com/arsenrinatuly/gashtar.git
cd gashtar
```

**Шаг 2. Подключить модель.** Создайте в корне проекта файл `.env` (шаблон — `.env.example`):

```
CQA_LLM_PROVIDER=openai
CQA_LLM_API_KEY=sk-...                     # ключ с platform.deepseek.com
CQA_LLM_MODEL=deepseek-flash
CQA_LLM_BASE_URL=https://api.deepseek.com
CQA_PRICE_IN_PER_M=0.30
CQA_PRICE_OUT_PER_M=1.20
CQA_CONCURRENCY=4
```

Без `.env` система тоже работает — в **офлайн-режиме** (правила по ключевым словам). Он менее точный и нужен как запасной.

**Шаг 3. Запустить**

```bash
python3 server.py
```

В консоли должна появиться строка `CQA: http://127.0.0.1:8000 | LLM: openai deepseek-flash`. Откройте **http://127.0.0.1:8000** — интерфейс и API работают на одном адресе.

Чтобы посмотреть интерфейс без ключа и без данных организаторов: `python3 server.py --seed-demo` (8 демо-диалогов RU/KZ/EN, включая звонок).

## 2. Загрузка и оценка диалогов (в том числе контрольных транскриптов)

**Через интерфейс** (раздел «Диалоги» → «Загрузка и оценка»):

1. В поле **GROUP ID** введите `DEV` или контрольный `group_id` от организаторов и нажмите **«Загрузить набор»**.
   Если API организаторов недоступен, откройте GET-ссылку в браузере, сохраните ответ как `.json` и нажмите **«Импорт JSON»**.
2. Выберите чек-лист и нажмите **«Оценить все»**. Диалоги оцениваются параллельно (`CQA_CONCURRENCY`), прогресс показан на экране. 65 диалогов занимают около 5 минут.
3. Откройте 2–3 диалога и проверьте подпись под итоговым баллом: там должно быть `llm:deepseek-flash`. Подпись `heuristic` означает, что модель не ответила (нет ключа или баланса) и сработал офлайн-режим. В этом случае исправьте `.env` и нажмите «Переоценить».

**Через консоль:**

```bash
python3 cli.py fetch <group_id>                       # загрузить набор из API организаторов
python3 cli.py import data/<файл>.json                # или из сохранённого JSON
python3 cli.py evaluate --dataset <group_id> --mode llm
python3 cli.py report --dataset <group_id>            # итоги по диалогам
```

`cli.py evaluate` оценивает диалоги по одному. Параллельная оценка идёт через сервер: кнопка «Оценить все» или `POST /api/evaluate/batch`.

**Выгрузка результатов для организаторов** (формат JSON 1.0 из приложения к гайду):

```bash
python3 cli.py export --dataset DEV --out results/dev/results.json
python3 cli.py export --dataset FBroker --out results/prod/results.json
```

Готовые файлы лежат в репозитории: `results/dev/results.json` (65 диалогов DEV) и `results/prod/results.json` (10 контрольных чатов FBroker). Оценки сделаны моделью DeepSeek V4.1 Flash (`deepseek-flash`).

В файл попадают все диалоги набора: 8 критериев с кодами `contact` … `critical`, значения `true`/`false`/`null` или балл шкалы, обоснование, номера реплик (с 1, по исходному массиву транскрипта), итог и `critical_flag`. Берётся последняя оценка с учётом решений по апелляциям. Если диалог не оценён, он записывается со `status: "error"`.

## 3. Замена критерия и повторная оценка

1. **Чек-листы** → откройте основной чек-лист.
2. Измените критерий: формулировку, вес, тип (Да/Нет, шкала, флаг), разрешён ли N/A, ступени шкалы. Или удалите критерий и добавьте новый.
3. **«Сохранить новую версию»** → **«Сделать основным»**.
4. **Диалоги** → выберите новую версию чек-листа → **«Оценить все»**.

Каждое сохранение создаёт версию `cl_xxx@N`. Прежние оценки хранят снимок чек-листа, на котором были сделаны, поэтому история не ломается. Новый критерий оценивает модель по его формулировке.

---

## 4. Апелляция и решение проверяющего

1. В карточке диалога у нужного критерия нажмите **«Оспорить оценку»**, напишите комментарий и отправьте.
2. **Апелляции** → выберите обращение. Проверяющий видит спорную оценку, объяснение модели, фрагмент диалога и комментарий.
3. Выберите **«Подтвердить»** или **«Изменить»** (новый ответ), укажите причину и нажмите **«Сохранить решение»**. Итог пересчитывается автоматически, в карточке видны исходная оценка, решение и финальный результат.

## 5. Как устроена оценка

1. **Нормализация транскрипта.** Роли `client`, `operator`, `bot`, `system`. Время в формате `MM:SS` (чаты) или ISO 8601 (звонки). Реплики бота и системные события используются как контекст: то, что клиент написал боту до эскалации, считается известным оператору.
2. **Факты о времени** вычисляет код, считая от передачи диалога оператору: первая реакция и паузы без предупреждения. Порог первой реакции (3 минуты) по условию в оценку не входит и включается полем `first_response_threshold_sec` в чек-листе.
3. **Модель** получает пронумерованные реплики и чек-лист. По каждому критерию она возвращает ответ (только из допустимых значений), объяснение, реплики-доказательства, проверенный участок и причину N/A.
4. **Ответ модели проверяется.** N/A там, где он запрещён, заменяется. Шкала приводится к ступени. Номера реплик и цитаты сверяются с транскриптом. Пропущенный критерий оценивают правила.
5. **Итог считает код, а не модель** (`backend/scoring.py`), по правилам чек-листа:
   - шкала переводится в баллы пропорционально весу;
   - вес критериев с N/A пропорционально перераспределяется между применимыми, максимум остаётся 100;
   - итог округляется до 2 знаков;
   - грубая ошибка отмечается отдельно и на баллы не влияет.
6. **Звонки.** Запись отдаётся через сервер (`GET /api/audio/<id>`): он находит mp3 за страницей-плеером организаторов, кэширует его в `data/audio/` и поддерживает перемотку. Клик по реплике переводит плеер к нужному моменту.

## 6. Модель, качество и стоимость

Чтобы выбрать модель, мы вручную разметили 60 чатов DEV по 8 критериям (`data/gold_dev.csv`; спорные места отмечены в колонке `disputed`) и сравнили подходы на одной и той же разметке:

| Движок | Совпадение с разметкой (480 ответов) | Средняя ошибка итога | Грубые ошибки | Цена одной оценки |
|---|---|---|---|---|
| **DeepSeek V4.1 Flash** (`deepseek-flash`) | **95,4% и 96,2%** (два прогона) | **2,9 и 2,7 балла** | **8 из 8, ложных 0** | ~$0,004 (~2 ₸) |
| Claude Sonnet 5.5 | 94,4% | 4,4 балла | 8 из 8, ложных 0 | ~$0,023 (~11 ₸) |
| Groq `openai/gpt-oss-120b` (бесплатно) | 87,5% | 6,7 балла | 8 из 8, ложных 1 | 0 |
| Офлайн-правила (без модели) | 89,4%* | 8,1 балла | 8 из 8, ложных 0 | 0 |

\* Правила настраивались на этих же диалогах, поэтому их цифра завышена. Модели под DEV не подгонялись.

- Цифры — это совпадение с **нашей** ручной разметкой. У экспертов заказчика трактовки спорных мест могут отличаться.
- Одна оценка — один вызов модели, стоимость каждой оценки сохраняется в поле `cost_usd`.
- Звонки DEV оценены, но в сравнение не входят: эталона по шумной расшифровке речи нет.

Проверить качество самостоятельно:

```bash
python3 cli.py evaluate --dataset DEV --mode llm
python3 cli.py compare                 # совпадение по критериям, средняя ошибка итога, грубые ошибки
python3 cli.py compare --details       # все расхождения с объяснениями модели
```

**Другие провайдеры** (переменные в `.env`):

| Вариант | Переменные |
|---|---|
| Любой OpenAI-совместимый API (DeepSeek, OpenAI, Groq, Gemini, OpenRouter) | `CQA_LLM_PROVIDER=openai`, `CQA_LLM_API_KEY`, `CQA_LLM_MODEL`, `CQA_LLM_BASE_URL` |
| Anthropic Claude | `CQA_LLM_PROVIDER=anthropic`, `CQA_LLM_API_KEY`, `CQA_LLM_MODEL`, `CQA_LLM_EFFORT` |
| Локально (Ollama) | `CQA_LLM_PROVIDER=openai`, `CQA_LLM_BASE_URL=http://localhost:11434/v1`, `CQA_LLM_MODEL=...` |

Цены для расчёта стоимости задаются в `CQA_PRICE_IN_PER_M` и `CQA_PRICE_OUT_PER_M` (USD за 1M токенов).

## 8. Структура

```
server.py              HTTP-сервер: REST API, статика web/, прокси аудио
cli.py                 консоль: fetch / import / evaluate / report / compare
backend/scoring.py     расчёт баллов, N/A, секции, валидация чек-листа
backend/evaluator.py   промпт, проверка ответа модели, апелляции, формат для UI
backend/llm.py         клиенты OpenAI-совместимых API и Anthropic (urllib)
backend/heuristic.py   офлайн-оценка по правилам RU/KZ/EN
backend/transcript.py  нормализация транскрипта, эскалация, паузы
backend/storage.py     SQLite (data/cqa.sqlite3), версии чек-листов
data/                  чек-лист по умолчанию, ручная разметка DEV, демо-набор
web/                   интерфейс (описание — web/FRONTEND_README.md)
tests/                 автотесты
```

**API** (все ответы в JSON):

```
GET  /api/health
POST /api/datasets/fetch             { group_id }
POST /api/conversations/import       JSON из API организаторов
GET  /api/conversations[?dataset=]   GET /api/conversations/{id}
GET  /api/checklists                 GET/PUT/DELETE /api/checklists/{id}   POST /api/checklists
POST /api/checklists/{id}/default
POST /api/evaluate                   { conversation_id, checklist_id?, mode? auto|llm|heuristic }
POST /api/evaluate/batch             { checklist_id?, dataset? | conversation_ids?, mode? }
GET  /api/jobs/{job_id}              GET /api/evaluations/{id}
POST /api/appeals                    { evaluation_id, criterion_id, comment }
GET  /api/appeals[?status=open|decided]
POST /api/appeals/{id}/decision      { action: confirm|change, new_answer?, reason }
GET  /api/audio/{conversation_id}    запись звонка
```

Ключи API хранятся только в `.env`. Файл `.env`, база `data/*.sqlite3` и кэш записей в git не попадают (`.gitignore`).
