# CQA — Conversation Quality Analytics

Русскоязычный фронтенд для просмотра диалогов, оценки по чек-листу, апелляций и пересмотра результатов. Реализован на HTML, CSS и JavaScript ES-модулях без сборщика и зависимостей.

## Запуск

Из корня проекта:

```bash
python3 -m http.server 8000
```

Откройте `http://localhost:8000/?demo=1`. Параметр `demo=1` принудительно включает демонстрационные данные. Без него интерфейс проверяет `GET /api/health` и автоматически включает демо-режим, если API недоступен. Состояние демо-режима хранится в `localStorage` браузера.

Для подключения сервера измените только атрибут `api-base` у `<cqa-app>` в `index.html`. По умолчанию он равен `/api`. Сервер может отдавать файлы этого каталога как статику.

## Что можно показать за пять минут

1. В «Диалогах» откройте `p1-ru-001` и нажмите «Оценить».
2. Откройте доказательство у критерия 04: реплика подсветится в транскрипте. У критерия 03 показано N/A.
3. Оспорьте критерий 04. Во вкладке «Апелляции» выберите «Изменить», ступень 20, укажите причину и сохраните решение. Новый итог появится сразу.
4. Во вкладке «Чек-листы» измените критерий и сохраните: появится новая версия. Сделайте её основной и запустите «Оценить все» в списке диалогов.

Демо-набор содержит четыре вымышленных диалога для проверки интерфейса (RU, KZ, EN и звонок). Демо-оценки предопределены и не являются результатом модели. Чтобы загрузить настоящий набор, используйте API или «Импорт JSON» с форматом `{ "records": [...] }` либо ответом организаторов `{ "data": { "dataset_group_id": "...", "records": [...] } }`.

## API

Используется контракт из ТЗ: `/health`, `/datasets/fetch`, `/conversations`, `/conversations/import`, `/checklists`, `/evaluate`, `/evaluate/batch`, `/jobs`, `/evaluations`, `/appeals`. Все запросы идут через `api.js` с единым `api-base`. Ошибки сервера `{ "error": "..." }` и `{ "errors": [...] }` выводятся в интерфейсе. В демо-режиме эти маршруты обслуживает `mock.js`.

Компоненты `<cqa-conversation-list>`, `<cqa-conversation-card>`, `<cqa-checklist-editor>` и `<cqa-appeals>` определены в `app.js` и работают внутри `<cqa-app>`.

## Правило начального чек-листа

Первоначальные восемь критериев, веса, шкалы и условия N/A взяты из PDF «Чек-лист качества чатов». Там прямо указано, что порог первой реакции в 3 минуты не входит в исходную оценку. В текстовом ТЗ он упомянут для критерия 06; при необходимости его можно добавить в новую версию через редактор. Итог и баллы по секциям считает бэкенд; локальный демо-адаптер воспроизводит пропорциональное перераспределение весов при N/A.
