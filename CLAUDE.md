# CQA — Conversation Quality Analytics (хакатон Freedom Broker)

Команда делает прототип за 24 часа: система оценивает работу оператора поддержки в чатах и звонках по настраиваемому чек-листу, показывает обоснования со ссылками на реплики, поддерживает апелляции. Общаемся на русском.

## Задание (из PDF организаторов)
- Две части. Первая — оценка: настройка чек-листа, оценка диалога, результат с доказательствами. Вторая — работа с результатом: карточка диалога, апелляция, решение проверяющего с пересчётом итога.
- Данные DEV: 65 диалогов. Из них 60 синтетических чатов (30 RU, 15 KZ, 15 EN) и 5 реальных звонков RU с `audio_url`.
- API организаторов: GET с параметром `group_id`. Через 23 часа после старта дадут контрольный `group_id`.
- На защите организаторы попросят заменить один критерий через интерфейс и применить новый чек-лист к диалогам.
- Защита — 5 минут:
  - интерфейс и диалог;
  - оценка, переход к реплике, N/A, итог;
  - апелляция и новый итог;
  - изменение критерия и повторная оценка.
- Если модель платная, нужно назвать её и стоимость одной оценки.
- Стоп-код через 24 часа после старта: последний коммит в открытом репозитории с README.

## Архитектура
- `server.py`: HTTP-сервер на стандартной библиотеке Python. Отдаёт REST API (`/api/...`) и статику из `web/`.
- `cli.py`: консольные команды `fetch`, `import`, `evaluate`, `report`, `compare`.
- `backend/scoring.py`: детерминированный расчёт итога. Шкала переводится в баллы пропорционально весу, вес критериев с N/A перераспределяется до 100, округление до 2 знаков, флаг грубой ошибки отдельно. **Итог считает код, а не модель.**
- `backend/evaluator.py`: промпт, вызов LLM, валидация ответа (допустимые значения, приведение шкалы к ступени, проверка индексов и цитат), офлайн-правила для пропущенных критериев, применение решений по апелляциям, формирование `Evaluation` для UI.
- `backend/llm.py`: клиенты Anthropic и OpenAI-совместимых API на urllib. Заголовок `User-Agent` обязателен: Cloudflare у Groq блокирует подпись `Python-urllib` (ошибка 1010).
- `backend/heuristic.py`: офлайн-оценка по ключевым словам RU/KZ/EN. Запасной режим.
- `backend/transcript.py`: нормализация транскрипта; время реакции считается **от эскалации на оператора**.
- `backend/storage.py`: SQLite (`data/cqa.sqlite3`). Каждое сохранение чек-листа создаёт новую версию `cl_xxx@N`, оценки хранят снимок чек-листа.
- `web/`: фронтенд (vanilla JS, Web Components) от разработчика команды. Ходит в API по контракту из ТЗ.
- `data/checklist_default.json`: 8 критериев из PDF с уточнениями.
- `data/gold_dev.csv`: ручная разметка 60 чатов DEV. Спорные места отмечены в колонке `disputed`.

## Запуск
```bash
python3 server.py                          # http://127.0.0.1:8000
python3 cli.py fetch DEV                   # или: python3 cli.py import data/dev.json
python3 cli.py evaluate --dataset DEV --mode llm|heuristic|auto
python3 cli.py compare --details           # сравнение последних оценок с gold_dev.csv
python3 -m unittest discover tests
```
`cli.py evaluate` работает последовательно. Параллельно оценивает сервер (`CQA_CONCURRENCY`):
`curl -s -X POST http://127.0.0.1:8000/api/evaluate/batch -H "Content-Type: application/json" -d '{"dataset":"DEV","mode":"llm"}'`, прогресс — `GET /api/jobs/<id>`.

LLM настраивается в `.env` (в git не коммитится): `CQA_LLM_PROVIDER` (anthropic|openai), `CQA_LLM_API_KEY`, `CQA_LLM_MODEL`, `CQA_LLM_BASE_URL`, `CQA_PRICE_IN_PER_M`, `CQA_PRICE_OUT_PER_M`, `CQA_CONCURRENCY`.

## Наблюдения по данным DEV
- Каждый чат начинается с бота AIM. Затем идёт системное событие передачи оператору: «Эскалация на оператора» / «Чат операторға жіберілді» / «Chat transferred to an agent». У звонков — «Агент присоединился».
- То, что клиент написал боту, оператору уже известно. Если оператор переспрашивает это, по критерию 02 ставится «Нет».
- Системные события: «Личность клиента подтверждена» → критерий 03; «Клиент покинул чат» / «Соединение прервано» → N/A по 07; «Оператор закрыл чат» без прощания → «Нет» по 07.
- Грубые ошибки в DEV:
  - перевести деньги лично: `ru-022`;
  - частная платная консультация: `ru-023`, `kz-013`, `en-013`;
  - оскорбление: `ru-029`;
  - данные счёта раскрыты без идентификации: `ru-009`, `kz-015`, `en-014`.
- Звонки — шумная расшифровка речи. Персональные данные замаскированы («[Персональные данные скрыты]»). Есть реплики оператора коллеге во время удержания клиента.

## Принятые трактовки (обсуждаемые)
1. Порог первой реакции 3 минуты по PDF «в оценку не входит», поэтому по умолчанию он выключен (`first_response_threshold_sec: null`). По критерию 06 учитывается только явное ожидание без предупреждения.
2. По 08 раскрытие сведений о счёте без идентификации считается раскрытием конфиденциальной информации.
3. По 07 вежливое прощание после того, как клиент подтвердил решение вопроса, засчитывается как «Да».

## Результаты на данный момент
- Офлайн-режим: совпадение с `gold_dev.csv` 89,4%, средняя ошибка итога 8,06, грубые ошибки найдены 8 из 8. Цифра завышена: правила подстраивались на DEV.
- Gemini `gemini-3.8-flash` на 10 диалогах: 96,2%, средняя ошибка итога 0,77. Но бесплатный лимит — всего 20 запросов в день, и ответ приходит за 1–2 минуты.
- Groq `openai/gpt-oss-120b` (бесплатно: около 1000 запросов в день, но 200 тыс. токенов в день, то есть примерно 45 оценок): работает. На `p1-ru-009` ошибся по 05 (не заметил игнорирование беспокойства клиента) и по 06.
- План Б: Claude API (Sonnet 5.5, около $1,3 за прогон DEV).

## Следующие шаги
1. Прогнать DEV на выбранной модели и разобрать `compare --details`. Правила 05 (вежливость ≠ реакция на беспокойство) и 06 (не смешивать с 02/03/07) уже уточнены в `checklist_default.json` — в существующей базе их нужно обновить через интерфейс или удалить `data/cqa.sqlite3`.
2. Звонки: плеер ходит через прокси `GET /api/audio/<id>` (скачивает запись Power Automate один раз, распаковывает JSON-обёртку `$content`, кэширует в `data/audio/`, поддерживает Range для перехода к реплике). Проверить на реальных `audio_url` DEV.
3. Отрепетировать 5-минутную защиту. Подготовить цифры: точность против разметки, стоимость одной оценки, время одной оценки.
4. На 23-м часу: `fetch <контрольный group_id>`, затем сразу пакетная оценка.
